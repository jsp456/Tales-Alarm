# Tales Alarm Raw Input 전체 패스스루 단축키 설계

작성일: 2026-08-11

상태: **철회됨 (2026-08-13).** 실기 검증에서 목표를 달성하지 못했고 기존에 동작하던 조합을 잃어 `RegisterHotKey` 구현으로 되돌렸다. 근거는 `2026-08-13-hotkey-detection-findings.md` 참고. 아래 내용은 기록으로만 남긴다.

## 1. 문서 관계

이 문서는 기존 `2026-08-09-tales-alarm-design.md`의 전역 단축키 설계를 보완하고, `RegisterHotKey`를 전제로 한 다음 내용을 대체한다.

- `4.3 전역 단축키`
- 단축키 등록 충돌과 복원에 관한 오류 처리
- `RegisterHotKey` 기반 통합 테스트와 최종 검증
- 단축키가 활성 프로그램에서 독점되는 것을 전제로 한 수용 기준

타이머 상태, 재입력 정책, 설정 저장, 알람, 창, 트레이 및 배포 설계는 기존 문서를 그대로 따른다.

## 2. 배경과 문제

현재 Tales Alarm은 Win32 `RegisterHotKey`로 단축키를 시스템 전역에 등록하고 `WM_HOTKEY`를 받아 타이머를 실행한다. 테일즈위버가 활성화된 상태에서는 수정키 없는 `F1`~`F12` 입력이 게임 안에서는 처리되지만 Tales Alarm의 `WM_HOTKEY`로 전달되지 않는다. 두 프로그램을 관리자 권한으로 실행해도 결과가 같으므로 권한 수준을 맞추는 방식으로는 해결되지 않는다.

사용자가 원하는 동작은 키를 Tales Alarm이 독점하는 것이 아니다. 동일한 물리 키 입력 한 번으로 테일즈위버의 게임 동작과 Tales Alarm의 타이머 동작이 함께 실행되어야 한다. 따라서 시스템 전역 단축키를 예약하는 방식 대신, 백그라운드에서 물리 키 입력을 수동으로 관찰하는 패스스루 방식이 필요하다.

## 3. 목표와 성공 기준

모든 사용자 지정 단축키를 Raw Input으로 감지하고 같은 입력을 활성 프로그램에서 계속 처리할 수 있게 한다.

완료 조건은 다음과 같다.

- 테일즈위버가 활성화된 상태에서 단일 `F1`~`F12` 입력이 게임 동작과 지정된 타이머를 동시에 실행한다.
- 수정키 없는 키와 Ctrl, Alt, Shift, Windows 수정키 조합 모두 동일한 패스스루 의미를 갖는다.
- 키를 길게 눌러 운영체제가 자동 반복 키다운을 보내도 타이머는 최초 키다운에만 한 번 반응한다.
- 키를 놓은 뒤 다시 누르면 타이머가 다시 반응한다.
- 앱 창이 트레이에 숨겨져 있어도 단축키가 작동한다.
- 단축키 캡처 중에는 타이머가 잘못 실행되지 않는다.
- 활성 프로그램의 키 입력을 차단하거나 합성하지 않는다.
- 일반 사용자 권한으로 동작하며 테일즈위버 프로세스나 보안 모듈에 접근하지 않는다.

## 4. 선택한 접근과 대안

### 4.1 선택: 모든 단축키를 Raw Input으로 처리

키보드 최상위 컬렉션을 `RIDEV_INPUTSINK | RIDEV_DEVNOTIFY`로 앱의 메인 창 핸들에 한 번 등록한다. `WM_INPUT`에서 물리 키의 키다운·키업을 읽고 현재 설정된 단축키와 정확히 일치하는 최초 키다운만 타이머 이벤트로 변환한다.

`RIDEV_NOLEGACY`와 `RIDEV_NOHOTKEYS`는 사용하지 않는다. 키보드 훅도 설치하지 않으며 입력을 합성하거나 대상 프로세스로 보내지 않는다. 따라서 Raw Input 관찰과 별개로 Windows와 활성 프로그램의 정상 입력 경로가 유지된다.

### 4.2 검토했지만 선택하지 않은 접근

- 단일 `F1`~`F12`만 Raw Input으로 처리하는 하이브리드 방식은 기존 동작의 변경 범위가 작지만, 단축키 종류에 따라 패스스루 여부가 달라지고 두 입력 경로의 중복·수명 주기를 함께 관리해야 한다.
- 사용자가 일반 모드와 호환 모드를 선택하는 방식은 유연하지만 새 UI와 설정 스키마가 필요하고, 모든 단축키를 활성 프로그램과 공유하려는 제품 방향에 불필요한 선택지를 추가한다.
- 저수준 키보드 훅은 전역 훅 수명과 타임아웃을 관리해야 하고 게임 보안 환경과 불필요하게 충돌할 여지가 있어 사용하지 않는다.
- 키 상태 폴링은 주기와 입력 사이의 짧은 키 입력을 놓칠 수 있고 기존 UI 갱신 주기에 입력 정확도를 의존시키므로 사용하지 않는다.

## 5. 사용자에게 보이는 동작

- 기존 단축키 입력 UI와 저장 형식은 유지한다.
- 설정한 단축키를 누르면 Tales Alarm과 현재 활성 프로그램이 모두 같은 입력에 반응한다.
- 예를 들어 `F5`를 등록하면 테일즈위버의 `F5` 동작과 타이머가 함께 실행된다.
- `Ctrl+S`나 `Alt+F4`처럼 활성 프로그램 자체 동작이 있는 조합을 등록해도 두 동작이 함께 실행된다. 이는 오류가 아니라 전체 패스스루의 명시적인 의미다.
- 일반 문자 하나를 단축키로 등록하면 다른 프로그램에서 해당 문자를 입력할 때도 타이머가 실행된다.
- `Ctrl+Alt+Delete`처럼 보안 데스크톱에서 처리되는 조합과 Windows가 선점하는 일부 시스템 조합은 감지를 보장하지 않는다.
- 단축키를 독점하지 않으므로 다른 프로그램이 같은 조합을 사용한다는 등록 충돌 오류는 더 이상 표시하지 않는다.

## 6. 아키텍처

### 6.1 Raw Input 네이티브 경계

새 Raw Input 네이티브 구성 요소는 다음 책임만 가진다.

- 일반 데스크톱 사용 페이지 `0x01`, 키보드 사용 ID `0x06`을 `RIDEV_INPUTSINK | RIDEV_DEVNOTIFY`로 등록한다.
- 앱 종료 시 같은 장치 클래스를 `RIDEV_REMOVE`로 해제한다.
- `WM_INPUT`의 `lParam`을 `GetRawInputData`로 읽어 장치 핸들, 가상 키, 스캔 코드, 확장 키 여부, 키다운·키업 여부를 앱 내부 이벤트로 변환한다.
- `WM_INPUT_DEVICE_CHANGE`에서 장치 도착과 제거 정보를 전달한다.
- 네이티브 실패 시 Win32 오류 코드를 반환한다.

네이티브 호출은 인터페이스 뒤에 두어 실제 Windows 입력 없이 단위 테스트할 수 있게 한다. WPF `Key` 변환, 단축키 비교, 타이머 선택은 이 구성 요소가 담당하지 않는다.

### 6.2 `GlobalHotkeyService`

`GlobalHotkeyService`는 이름과 외부 이벤트 계약을 유지하되 내부 구현을 Raw Input 조정자로 바꾼다.

- 창 핸들이 연결되면 키보드 Raw Input을 한 번 등록한다.
- 현재 타이머 바인딩을 메모리에 보관한다.
- Raw Input 이벤트의 가상 키를 기존 `HotkeyGesture`가 사용하는 WPF `Key` 의미로 정규화한다.
- 장치별 키다운 상태와 수정키 상태를 관리한다.
- 최초 키다운에서 키와 수정키가 저장된 제스처와 정확히 같을 때만 기존 `HotkeyPressed` 이벤트를 발생시킨다.
- 단축키 캡처 임대가 하나 이상 활성화되어 있으면 상태는 수신하되 타이머 이벤트는 발생시키지 않는다.
- 설정 적용, 캡처 종료, 장치 제거 시 관련 눌림 상태를 초기화한다.
- 종료 시 장치 등록과 이벤트 참조를 정리한다.

`Apply`는 더 이상 키별 네이티브 등록을 수행하지 않는다. 기존과 같이 중복 타이머 번호, 중복 제스처, 수정키만 있는 제스처를 거부하고, Raw Input 장치가 사용 가능한 상태에서만 검증된 바인딩 스냅샷을 교체한다. 설정 파일 저장이 실패하면 `MainViewModel`의 기존 복원 경로가 이전 바인딩 스냅샷을 다시 적용한다.

### 6.3 WPF 메시지 연결

`App`의 `HwndSourceHook`은 메시지 번호와 `wParam`뿐 아니라 `lParam`도 서비스에 전달한다.

- `WM_INPUT`은 Raw Input 이벤트로 해석한다.
- `WM_INPUT_DEVICE_CHANGE`는 제거된 장치의 키 상태를 정리하는 데 사용한다.
- `WM_HOTKEY` 처리는 제거한다.
- `WM_INPUT`을 읽은 뒤에도 WPF 훅의 `handled`를 `true`로 설정하지 않는다. Windows의 기본 메시지 처리를 계속 통과시켜 입력 자원 정리와 패스스루 의미를 보존한다.

메인 창은 트레이로 숨길 때 폐기되지 않으므로 동일한 창 핸들과 Raw Input 등록이 앱 수명 동안 유지된다.

## 7. 입력 정규화와 상태 관리

### 7.1 키와 수정키

- Raw Input 가상 키를 기존 단축키 캡처 UI와 같은 WPF `Key` 값으로 변환한다.
- 좌우 Ctrl, Alt, Shift, Windows 키는 각각 하나의 저장용 수정키 플래그로 합친다.
- 내부 상태는 장치별로 유지하되, 제스처 비교 시 현재 연결된 장치들의 수정키 상태를 합산한다. 한 키보드에서 Ctrl을 누르고 다른 키보드에서 본키를 누르는 경우에도 하나의 조합으로 본다.
- 주 키가 수정키뿐인 제스처는 기존과 동일하게 유효하지 않다.
- 장치가 보고하는 가짜 키나 지원하지 않는 가상 키는 무시한다.
- 문자와 OEM 기호 키는 기존 WPF 단축키 값과 일치하도록 가상 키 기준으로 변환하며 한국어·영어 입력 배열에서 검증한다.

### 7.2 자동 반복과 재무장

각 장치의 주 키에 대해 최초 키다운만 새 입력으로 인정한다. 같은 장치와 키에 대한 추가 키다운은 키업이 오기 전까지 자동 반복으로 보고 무시한다. 키업이 오면 해당 키를 다시 입력 가능한 상태로 바꾼다.

다음 경계에서는 눌림 상태를 초기화한다.

- 단축키 설정 적용
- 최종 단축키 캡처 임대 종료
- 키보드 장치 제거
- Raw Input 재등록
- 서비스 종료

이를 통해 설정 변경이나 장치 제거 중 키업을 받지 못해 특정 키가 영구적으로 눌린 것으로 남는 상황을 방지한다.

### 7.3 일치와 전달

주 키의 최초 키다운 시점에 정규화된 키와 현재 수정키 집합을 하나의 `HotkeyGesture`로 만든다. 저장된 제스처와 정확히 같은 바인딩이 있으면 해당 타이머 번호로 `HotkeyPressed`를 한 번 발생시킨다. 중복 제스처는 설정 검증에서 거부되므로 한 입력이 두 타이머를 동시에 실행하지 않는다.

일치하지 않는 입력은 즉시 폐기한다. 입력 문자, 연속 입력 내용, 장치 이름, 일치하지 않은 키는 저장하거나 진단 로그에 남기지 않는다.

## 8. 주요 데이터 흐름

단축키 입력의 데이터 흐름은 다음과 같다.

1. 사용자가 물리 키를 누른다.
2. Windows는 활성 프로그램의 정상 입력 경로와 Tales Alarm의 `WM_INPUT` 경로에 입력을 전달한다.
3. 활성 프로그램은 기존 동작을 수행한다.
4. Tales Alarm은 Raw Input 이벤트를 정규화하고 장치별 반복 상태와 수정키를 확인한다.
5. 저장된 제스처와 일치하면 `HotkeyPressed`에 타이머 번호를 전달한다.
6. `MainViewModel`은 기존과 동일하게 해당 `TimerViewModel.HandleHotkey`를 호출한다.
7. 타이머는 현재 상태와 저장된 재입력 정책에 따라 시작, 재시작, 일시정지·재개 또는 무시를 수행한다.

화면 버튼, 타이머 상태 전이, 완료 알람 흐름은 변경하지 않는다.

## 9. 오류 처리와 복구

- Raw Input 등록 실패 시 앱 시작을 중단하지 않는다. 화면 버튼과 타이머는 계속 사용할 수 있게 두고 단축키 입력만 비활성화하며 Win32 오류 코드를 사용자 메시지와 진단 로그에 남긴다.
- 패스스루 의미를 바꾸는 `RegisterHotKey` 방식으로 자동 대체하지 않는다.
- `GetRawInputData`가 실패하거나 크기·형식이 유효하지 않은 이벤트는 무시하고 오류를 진단 로그에 남긴다. 이후 입력 처리는 계속한다.
- 알 수 없는 장치 제거 이벤트는 무시한다.
- 장치 제거 시 해당 장치의 키와 수정키 상태를 모두 지운다.
- 설정 저장 실패 시 기존 설정과 이전 바인딩 스냅샷으로 복원한다.
- 단축키 충돌은 오류로 취급하지 않는다. 같은 키를 활성 프로그램이 처리하는 것은 요구된 패스스루 동작이다.
- 일치하지 않은 키 입력과 실제 입력 내용은 로그에 남기지 않는다.

## 10. 보안과 호환성 경계

이 기능은 키보드 입력을 관찰만 한다.

- `SetWindowsHookEx`를 사용하지 않는다.
- `SendInput`, `keybd_event` 또는 다른 입력 주입 API를 사용하지 않는다.
- 테일즈위버의 프로세스, 메모리, 창 또는 설치 파일에 접근하지 않는다.
- BlackCipher 및 다른 게임 보안 프로세스를 탐지, 종료, 변경 또는 우회하지 않는다.
- 입력 장치와 무관한 프로세스 정보는 수집하지 않는다.

Raw Input은 앱이 포그라운드가 아닐 때도 키보드 이벤트를 전달하므로 모든 키 이벤트를 기술적으로 수신한다. 서비스는 제스처 비교에 필요한 키다운 상태와 수정키 상태만 메모리에 일시적으로 유지하고, 입력 내용은 파일이나 설정에 저장하지 않는다.

## 11. 테스트 전략

### 11.1 단위 테스트

가짜 Raw Input 네이티브 API와 정규화된 키 이벤트를 사용해 다음을 검증한다.

- 창 연결 시 올바른 장치 등록이 한 번 수행되고 종료 시 해제되는지
- 장치 등록 실패가 단축키 비활성화 오류로 반환되는지
- 수정키 없는 키와 각 수정키 조합이 정확히 일치할 때만 대상 타이머 이벤트가 발생하는지
- 추가 수정키가 눌린 경우 다른 제스처로 취급하는지
- 같은 장치의 반복 키다운이 한 번만 전달되고 키업 후 다시 전달되는지
- 서로 다른 키보드의 상태가 장치별로 분리되고 수정키는 전체 장치에서 합산되는지
- 장치 제거, 설정 적용, 캡처 종료가 눌림 상태를 초기화하는지
- 캡처 임대가 중첩된 동안 이벤트가 억제되고 마지막 임대가 끝난 뒤에만 다시 전달되는지
- 중복 제스처와 수정키만 있는 제스처가 거부되는지
- 알 수 없는 키, 잘못된 Raw Input, 등록되지 않은 장치 이벤트가 타이머를 실행하지 않는지
- 설정 저장 실패 후 이전 바인딩을 다시 적용할 수 있는지

### 11.2 Windows 통합 테스트

- 실제 창 핸들에 키보드 장치를 `RIDEV_INPUTSINK | RIDEV_DEVNOTIFY`로 등록하고 해제한다.
- 등록 플래그에 `RIDEV_NOLEGACY`와 `RIDEV_NOHOTKEYS`가 포함되지 않는지 확인한다.
- WPF 메시지 훅이 `WM_INPUT`의 `lParam`을 전달하고 메시지를 처리 완료로 표시하지 않는지 확인한다.
- 창을 숨겼다가 복원해도 동일한 창 핸들과 입력 등록을 유지하는지 확인한다.
- 기존 단축키 캡처 UI, 설정 저장·복원, 타이머별 라우팅 테스트가 새 입력 경로에서도 통과하는지 확인한다.
- `RegisterHotKey`, `UnregisterHotKey`, `WM_HOTKEY`에 대한 런타임 의존성이 제거됐는지 확인한다.

### 11.3 수동 호환성 검증

게시된 Windows x64 실행 파일을 일반 사용자 권한으로 실행하고 다음을 확인한다.

- Tales Alarm 창이 보이는 상태와 트레이에 숨은 상태 모두에서 단축키가 작동하는지
- 테일즈위버가 활성화된 상태에서 지정한 단일 F키가 게임 동작과 타이머를 동시에 실행하는지
- 테일즈위버의 창 모드와 전체 화면 모드에서 동일하게 동작하는지
- 키를 길게 눌러도 타이머가 한 번만 반응하고 놓았다 다시 누르면 다시 반응하는지
- `Ctrl+F2` 같은 수정키 조합이 정확한 수정키 상태에서만 작동하는지
- 설정 화면에서 단축키를 다시 입력할 때 타이머가 실행되지 않는지
- 일반 프로그램에서 등록한 단축키를 누르면 그 프로그램의 동작과 타이머가 함께 실행되는지
- 테스트 중 테일즈위버가 종료되거나 게임 보안 경고가 표시되지 않는지

## 12. 수용 기준

다음 시나리오가 모두 성공하면 전체 패스스루 단축키 기능을 완료한 것으로 본다.

1. 타이머 1에 `F2`, 타이머 2에 `F5`를 저장하고 앱을 트레이로 숨긴다.
2. 테일즈위버를 활성화한 상태에서 `F2`를 누르면 게임의 `F2` 동작과 타이머 1이 함께 실행된다.
3. 같은 조건에서 `F5`를 누르면 게임의 `F5` 동작과 타이머 2가 함께 실행된다.
4. 각 키를 길게 눌러도 대상 타이머는 한 번만 반응한다.
5. 키를 놓았다 다시 누르면 저장된 재입력 정책에 따라 대상 타이머가 다시 반응한다.
6. 수정키 조합은 저장된 수정키 집합과 정확히 일치할 때만 실행된다.
7. 단축키 캡처, 설정 저장 실패 복원, 창 숨김·복원 및 앱 종료가 입력 상태를 손상시키지 않는다.
8. Tales Alarm은 키를 차단하거나 주입하지 않으며 테일즈위버와 게임 보안 프로세스에 접근하지 않는다.

## 13. 제외 범위

- 프로그램별 단축키 프로필
- 테일즈위버 실행 또는 포그라운드 상태 감지
- 일반 전역 단축키와 패스스루 단축키를 선택하는 UI
- 활성 프로그램에서 키 동작을 차단하는 옵션
- 키 시퀀스, 매크로, 연타 또는 입력 재생
- 키보드·마우스 입력 주입
- 게임 보안 모듈 우회 또는 예외 처리
- 보안 데스크톱과 운영체제 예약 단축키 지원 보장
- 설정 스키마 변경
