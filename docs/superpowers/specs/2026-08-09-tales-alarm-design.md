# Tales Alarm Windows 데스크톱 앱 설계

작성일: 2026-08-09

상태: 사용자 승인 완료

## 1. 목표

Tales Alarm은 Windows에서 두 개의 카운트다운 타이머를 동시에 실행하는 독립 실행형 데스크톱 앱이다. 각 타이머는 전역 단축키로 시작할 수 있고, 실행 중 같은 단축키가 다시 입력됐을 때의 동작을 개별 설정할 수 있다. 앱 창을 닫아도 시스템 트레이에서 계속 실행하며, 내장 알람 또는 사용자가 가져온 음원을 설정한 시간 동안 재생한다.

완료 조건은 다음과 같다.

- 타이머 1과 타이머 2가 서로 영향을 주지 않고 동시에 동작한다.
- 기본 시간은 각각 20분과 30분이며 00:00:01~999:59:59 범위에서 시·분·초 단위로 변경하고 저장할 수 있다.
- 기본 전역 단축키는 각각 `F4`와 `F8`이며 사용자가 변경하고 저장할 수 있다.
- 타이머가 실행 중일 때 같은 단축키를 다시 누르는 동작은 타이머별로 `처음부터 다시 시작`, `일시정지·재개`, `입력 무시` 중 선택한다. 기본값은 `처음부터 다시 시작`이다.
- 앱에는 직접 제작한 1.5초 길이의 2단 전자 차임 WAV 파일이 기본 음원으로 포함된다.
- 사용자는 WAV 또는 MP3 파일을 앱 안에서 가져오고, 미리 듣거나 기본 음원으로 복원할 수 있다.
- 알람 재생 시간은 0.1초 단위 숫자로 입력하며 범위는 0.1~60.0초, 기본값은 1.5초다.
- 음원이 설정된 재생 시간보다 짧으면 필요한 만큼 반복하고, 길면 설정 시간이 되면 중단한다.
- 창의 닫기 버튼은 앱을 종료하지 않고 시스템 트레이로 숨긴다.
- 최종 결과물은 대상 PC에 .NET을 별도로 설치하지 않아도 실행되는 Windows x64 단일 실행 파일이다.

## 2. 제외 범위

- Windows 로그인 시 자동 시작
- 세 번째 이상의 타이머
- 온라인 동기화, 계정, 네트워크 기능
- 예약 시각 알람 또는 반복 일정
- 서로 다른 타이머에 서로 다른 알람 음원을 지정하는 기능
- 설치 관리자 또는 자동 업데이트

## 3. 기술 선택과 배포

앱은 C#과 WPF를 사용하고 `net10.0-windows`를 대상으로 한다. .NET 10은 설계 시점의 지원 중인 LTS 버전이며 WPF는 Windows 데스크톱 기능, Win32 전역 단축키, 트레이 통합에 적합하다.

배포 빌드는 다음 원칙을 따른다.

- 대상 런타임: `win-x64`
- 자체 포함 배포: 활성화
- 단일 파일 게시: 활성화
- 트리밍: 비활성화하여 WPF 리소스와 리플렉션 호환성을 보존
- 기본 알람 WAV와 앱 아이콘: 어셈블리에 포함
- 사용자 설정과 가져온 음원: 실행 파일 옆이 아닌 `%LocalAppData%\TalesAlarm` 아래에 저장

개발 환경에는 .NET 10 SDK가 필요하다. 최종 게시된 앱의 실행에는 SDK나 별도 .NET 런타임이 필요하지 않다.

## 4. 아키텍처

### 4.1 프레젠테이션 계층

- `MainWindow`: 두 타이머 카드와 공통 음원 설정을 표시한다.
- `MainViewModel`: 앱 전체 명령, 설정 저장, 오류 표시를 조정한다.
- `TimerViewModel`: 타이머 한 개의 표시 상태와 사용자 입력을 관리한다.
- WPF 데이터 바인딩과 명령을 사용해 화면 코드와 타이머 로직을 분리한다.

### 4.2 타이머 도메인

각 타이머는 독립된 `CountdownTimer` 인스턴스로 표현한다. 상태는 `Idle`, `Running`, `Paused`, `Completed` 중 하나다.

타이머는 UI 갱신 횟수를 시간의 기준으로 사용하지 않는다. `TimeProvider`의 단조 증가 타임스탬프를 이용해 실제 경과 시간을 계산한다. 화면은 약 100ms 간격으로 갱신하지만 남은 시간은 항상 기준 시점과 현재 시점의 차이에서 계산하므로 UI 스레드가 잠시 지연돼도 누적 오차가 생기지 않는다.

주요 동작은 다음과 같다.

- `Start`: 설정된 전체 시간으로 실행한다.
- `Restart`: 설정된 전체 시간으로 즉시 다시 실행한다.
- `Pause`: 현재 남은 시간을 고정한다.
- `Resume`: 고정된 남은 시간부터 새 기준 시점을 잡아 실행한다.
- `Reset`: 실행을 멈추고 설정된 전체 시간의 대기 상태로 돌아간다.
- `HandleHotkey`: 대기·완료 상태에서는 시작하고, 실행·일시정지 상태에서는 선택된 재입력 정책을 적용한다.

설정 시간이 변경돼도 이미 실행 중인 카운트다운의 목표 시간은 바꾸지 않는다. 변경값은 다음 시작 또는 초기화부터 적용한다.

### 4.3 전역 단축키

`GlobalHotkeyService`는 Win32 `RegisterHotKey`와 WPF `HwndSource` 메시지 훅을 감싼다.

- 기본값은 수정키 없는 `F4`와 `F8`이다.
- 키 입력 UI는 단일 키 및 Ctrl, Alt, Shift, Windows 수정키 조합을 캡처할 수 있다.
- 두 타이머에 같은 조합은 저장할 수 없다.
- 설정을 적용할 때 후보 단축키 두 개를 하나의 변경 단위로 등록한다.
- 후보 등록이 실패하면 후보 등록을 모두 해제하고 이전의 정상 설정을 복원한다.
- 등록 실패 이유와 충돌한 키를 사용자에게 표시한다.

### 4.4 설정 저장

`SettingsService`는 `%LocalAppData%\TalesAlarm\settings.json`에 다음 값을 저장한다.

- 설정 스키마 버전
- 두 타이머의 시·분·초 설정값
- 두 타이머의 단축키와 수정키
- 두 타이머의 단축키 재입력 정책
- 기본 음원 또는 사용자 음원 선택 상태
- 사용자 음원 파일명
- 알람 재생 시간

저장은 같은 폴더의 임시 파일에 먼저 기록하고 성공 후 기존 파일과 교체한다. 앱 시작 시 파일이 없으면 기본 설정을 만들고, JSON이 손상됐거나 스키마가 유효하지 않으면 손상 파일을 타임스탬프가 붙은 백업 이름으로 보존한 뒤 기본 설정으로 복구한다.

### 4.5 알람 음원

`AlarmAudioService`는 UI나 타이머 로직이 실제 재생 기술을 알지 않아도 되도록 `IAudioBackend` 뒤에 둔다.

- 기본 음원은 코드로 생성한 1.5초 2단 전자 차임 WAV다.
- 사용자 음원은 파일 선택 창에서 WAV 또는 MP3를 고르면 `%LocalAppData%\TalesAlarm\Audio`로 복사한다.
- 복사된 파일에는 충돌하지 않는 앱 관리 이름을 사용하므로 사용자가 원본 파일을 이동하거나 삭제해도 재생된다.
- 후보 파일을 앱 관리 임시 이름으로 복사한 뒤 실제로 열 수 있는지 확인한다. 확인과 설정 저장이 모두 성공한 뒤에만 기존 사용자 음원을 지우고 후보를 활성 파일로 바꾼다. 실패하면 기존 음원과 설정을 그대로 유지한다.
- `미리 듣기`와 실제 알람은 동일한 재생 경로를 사용한다.
- 음원 종료 이벤트가 재생 제한 시간보다 먼저 오면 위치를 처음으로 되돌려 반복한다.
- 단조 증가 시간을 기준으로 설정된 재생 제한에 도달하면 음원을 정지한다.
- 가져온 음원을 열거나 재생할 수 없으면 오류를 알리고 해당 재생부터 기본 차임을 사용한다.

동시에 여러 오디오 인스턴스를 겹쳐 재생하지 않는다. 두 타이머가 같은 UI 갱신 주기에서 완료되면 한 번만 알람을 시작한다. 이미 알람이 재생 중일 때 다른 타이머가 완료되면 음원을 중첩하지 않고 재생 종료 시각을 새 완료 시점부터 설정된 재생 시간만큼 다시 잡는다.

### 4.6 트레이와 단일 인스턴스

`TrayService`는 Windows 알림 영역 아이콘을 제공한다.

- 창 닫기 요청은 취소되고 창만 숨겨진다.
- 트레이 아이콘 두 번 클릭 또는 `열기` 메뉴로 창을 복원하고 전면에 표시한다.
- `종료` 메뉴만 실제 앱 종료를 수행한다.
- 트레이에 숨겨진 동안에도 타이머, 전역 단축키, 알람은 계속 동작한다.

앱은 이름이 지정된 뮤텍스로 중복 실행을 감지한다. 두 번째 프로세스는 이름이 지정된 파이프로 기존 프로세스에 창 표시 요청을 전달하고 종료한다. 따라서 중복된 전역 단축키 등록과 별도 타이머 인스턴스가 생기지 않는다.

### 4.7 주요 데이터 흐름

전역 단축키 또는 화면 버튼 입력은 `MainViewModel`을 거쳐 대상 `CountdownTimer`의 명령으로 전달된다. 타이머 완료 이벤트는 `MainViewModel`에서 같은 갱신 주기의 완료들을 하나로 모아 `AlarmAudioService`에 전달한다. UI 갱신은 타이머 상태를 읽기만 하며 시간 계산이나 오디오 재생을 직접 수행하지 않는다.

설정 적용 시 전체 입력을 먼저 검증한 뒤 후보 단축키 등록, 설정 파일 저장 순으로 처리한다. 둘 중 하나라도 실패하면 단축키와 메모리 설정을 이전 상태로 되돌린다. 성공하면 새 단축키와 재입력 정책은 즉시 적용된다. 새 타이머 시간은 실행 중인 카운트다운에는 영향을 주지 않고 다음 시작 또는 초기화부터 사용한다.

## 5. 화면과 사용자 흐름

### 5.1 메인 화면

두 타이머 카드를 나란히 배치한다. 각 카드에는 다음 요소가 있다.

- 타이머 번호와 상태 배지
- 큰 `시:분:초` 남은 시간
- 설정 시간의 시·분·초 숫자 입력
- 전역 단축키 캡처 입력
- 재입력 동작 선택
- `시작`, `일시정지·재개`, `초기화` 버튼
- 해당 타이머 설정의 유효성 오류 표시

공통 음원 영역에는 현재 음원명, `음원 변경`, `미리 듣기`, `기본음 복원`, 재생 시간 숫자 입력을 둔다. 설정 적용 버튼은 전체 입력을 검증하고 전역 단축키 등록과 설정 저장을 하나의 사용자 동작으로 수행한다.

`시작` 버튼은 대기·완료 상태에서는 시작하고 실행·일시정지 상태에서는 설정된 전체 시간으로 명시적으로 재시작한다. `일시정지·재개` 버튼은 실행 상태에서 일시정지하고 일시정지 상태에서 재개하며, 다른 상태에서는 비활성화된다. `초기화`는 실행을 멈추고 현재 저장된 설정 시간의 대기 상태로 돌아간다. 이 버튼 동작은 단축키 재입력 정책과 무관하다.

### 5.2 기본값

| 항목 | 타이머 1 | 타이머 2 |
|---|---:|---:|
| 시간 | 00:20:00 | 00:30:00 |
| 전역 단축키 | F4 | F8 |
| 재입력 동작 | 처음부터 다시 시작 | 처음부터 다시 시작 |

공통 기본 음원은 내장 2단 차임이고 재생 시간은 1.5초다.

### 5.3 단축키 상태별 동작

| 현재 상태 | 처음부터 다시 시작 | 일시정지·재개 | 입력 무시 |
|---|---|---|---|
| 대기 | 시작 | 시작 | 시작 |
| 실행 중 | 전체 시간으로 재시작 | 일시정지 | 변화 없음 |
| 일시정지 | 전체 시간으로 재시작 | 재개 | 변화 없음 |
| 완료 | 전체 시간으로 시작 | 전체 시간으로 시작 | 전체 시간으로 시작 |

타이머가 0에 도달하면 상태를 `완료`로 바꾸고 알람 서비스에 한 번만 완료 이벤트를 보낸다. 화면은 00:00:00을 유지하며 다음 단축키 입력이나 시작 버튼으로 다시 시작할 수 있다.

## 6. 유효성 검사와 오류 처리

- 타이머 설정 시간은 1초 이상이어야 한다.
- 시·분·초 입력은 음수가 될 수 없고 시는 0~999, 분과 초는 각각 0~59 범위다.
- 알람 재생 시간은 0.1~60.0초이며 소수 첫째 자리까지만 허용한다.
- 두 단축키는 서로 달라야 한다.
- Windows가 단축키 등록을 거부하면 이전 등록과 저장 설정을 유지하고 충돌 메시지를 표시한다.
- 음원 선택 취소는 기존 설정을 바꾸지 않는다.
- 파일 복사 실패, 지원하지 않는 형식, 재생 실패는 사용자에게 설명하고 기존 음원 또는 기본 음원을 유지한다.
- 설정 손상 복구는 앱 시작을 막지 않으며 복구 사실과 백업 위치를 알린다.
- 예상하지 못한 UI 명령 오류는 앱 전체를 종료시키지 않고 사용자 메시지와 `%LocalAppData%\TalesAlarm\Logs\app-YYYYMMDD.log` 진단 로그로 남긴다. 로그는 최근 7일분만 보존한다.

## 7. 테스트 전략

### 7.1 단위 테스트

- 가짜 `TimeProvider`로 두 타이머가 동시에 실행돼도 각각 정확한 남은 시간을 갖는지 검증
- UI 갱신이 지연된 경우에도 실제 경과 시간으로 보정되는지 검증
- 시작, 재시작, 일시정지, 재개, 초기화, 완료 상태 전이 검증
- 세 가지 재입력 정책을 모든 타이머 상태에서 검증

## 8. 수용 기준

다음 시나리오가 모두 성공하면 기능 구현을 완료한 것으로 본다.

1. 새 설정에서 앱을 실행하면 20분/F4와 30분/F8 타이머가 표시된다.
2. F4와 F8을 연속으로 눌러 두 타이머를 동시에 실행할 수 있다.
3. 각 타이머에 서로 다른 재입력 정책을 저장하고 예상한 동작을 확인할 수 있다.
4. 창을 닫아 트레이로 숨긴 뒤에도 단축키와 타이머가 작동한다.
5. 타이머가 완료되면 직접 제작한 차임이 기본 1.5초 동안 재생된다.
6. 짧은 사용자 음원을 가져와 더 긴 재생 시간을 지정하면 설정 시간이 끝날 때까지 반복된다.
7. 앱을 종료하고 다시 실행해도 시간, 단축키, 정책, 음원, 재생 시간이 복원된다.
8. 단축키 충돌, 손상된 설정, 재생 불가능한 음원 때문에 앱이 비정상 종료되지 않는다.
9. 게시된 단일 `.exe`가 .NET이 설치되지 않은 Windows x64 환경에서도 실행된다.
