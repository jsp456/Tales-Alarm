# 테일즈위버 활성 시 단축키 감지 조사 결과와 Raw Input 철회

작성일: 2026-08-13

상태: 확정. `RegisterHotKey` 방식으로 되돌림.

## 1. 배경

`2026-08-11-pass-through-hotkeys-design.md`는 테일즈위버 활성 시 수정키 없는 `F1`~`F12`가 타이머로 전달되지 않는 문제를 풀기 위해 `RegisterHotKey`를 Raw Input 관찰로 교체했다. 구현과 자동 검증은 통과했지만(테스트 169개), 실제 테일즈위버 검증은 미뤄져 있었다.

사용자가 실기 검증한 결과 **문제가 해결되지 않았고, 오히려 이전보다 나빠졌다.** 이 문서는 그 뒤 수행한 조사 결과와 철회 근거를 남긴다.

## 2. 사용자 실기 확인 사항

- Raw Input 빌드에서 테일즈위버가 활성이면 **게임이 쓰는 키가 타이머로 전달되지 않는다.** 게임 동작은 정상이다.
- `RegisterHotKey` 빌드에서도 수정키 없는 `F1`~`F12`와 숫자 키는 전달되지 않는다. 이는 원래부터 있던 제한이다.
- **`Ctrl+1` 같은 조합은 `RegisterHotKey` 빌드에서 동작하지만 Raw Input 빌드에서는 동작하지 않는다.** 즉 Raw Input 전환으로 잃은 기능이 있다.
- `RegisterHotKey` 빌드에서 단축키를 등록해도 **게임은 같은 키를 계속 받는다.** 이 게임이 창 메시지가 아닌 경로로 키를 읽기 때문으로 보이며, 결과적으로 `RegisterHotKey` 방식이 이 조합에서는 실질적인 패스스루로 동작한다.
- Raw Input 빌드는 Tales Alarm 창이 활성일 때는 정상 동작한다. 즉 눌림 상태가 영구히 고착되는 문제는 아니다.

## 3. 계측으로 확인한 사실

게임을 실행할 수 없는 환경이었으므로, 후보 메커니즘을 로컬에서 재현해 계측했다. 도구는 `tools/RawInputProbe`(수신 계측)와 `tools/ForegroundAntagonist`(가로채기 재현)이며, 판정은 사람의 청각이 아니라 대조키 `Q`와 프로브 로그로 했다.

| 관찰 방식 | 포그라운드 앱이 F키를 삼킬 때 | 대조키 `Q` |
|-----------|------------------------------|-----------|
| `RIDEV_INPUTSINK`(구현안) | 수신 0 | 수신됨 |
| `RIDEV_INPUTSINK \| RIDEV_EXINPUTSINK` | 수신 0 | 수신됨 |
| `GetAsyncKeyState` 폴링 | 수신 0 | 수신됨 |

세 경우 모두 프로브는 하트비트로 생존이 확인됐고 대조키는 수신했다. 즉 "못 받은 것"이지 "안 누른 것"이 아니다.

확정된 세 가지:

1. **포그라운드 앱이 저수준 키보드 훅으로 특정 키를 삼키면, 사용자 모드에서 그 키를 관찰할 방법이 없다.** Raw Input도 폴링도 동일하게 막힌다.
2. **`RIDEV_EXINPUTSINK`는 수신 범위를 넓히는 플래그가 아니다.** 포그라운드 앱이 해당 입력을 소비하지 않을 때만 받는 **좁히는** 플래그이며, 상대역이 키보드 Raw Input을 등록하자 수신이 통째로 0이 됐다. 제품에 추가했다면 회귀였다.
3. 포그라운드 앱이 `RIDEV_NOLEGACY | RIDEV_NOHOTKEYS`로 키보드를 독점하는 것만으로는 `RIDEV_INPUTSINK` 수신을 막지 못한다. 이 메커니즘은 원인이 아니다.

상세 표와 로그 해석은 `tools/RawInputProbe/README.md`에 있다.

## 4. 결론

- 테일즈위버 활성 시 수정키 없는 `F1`~`F12`와 숫자 키를 감지하는 것은 **두 방식 모두에서 불가능하다.** Raw Input 전환은 이 목표를 달성하지 못했다.
- 반면 Raw Input 전환은 `Ctrl+1` 같이 이전에는 동작하던 조합을 잃었다. 따라서 이 변경은 순손실이다.
- 남은 유일한 해결책은 제품 밖에 있다. **게임 안에서 해당 스킬 키를 `F1`~`F12`와 숫자 키 밖으로 옮기면** 게임도 그 키로 동작하고 Tales Alarm도 그 키를 감지한다.

## 5. 조치

`a362f27`, `6f0e85d`, `fcfadd4`가 도입한 Raw Input 경로를 `src/`와 `tests/`에서 제거하고 `RegisterHotKey` 구현으로 되돌렸다. `2026-08-11-pass-through-hotkeys-design.md`와 그 구현 계획은 **철회 상태**이며, 기존 `2026-08-09-tales-alarm-design.md`의 `4.3 전역 단축키`가 다시 유효하다.

`tools/` 아래 진단 도구는 조사 근거로 남긴다. 제품에는 포함되지 않으며 `TalesAlarm.sln`에도 들어 있지 않다.

## 6. 하지 않은 것

키보드 훅 설치, 입력 주입·합성, 게임 보안 모듈 탐지·우회, 테일즈위버 프로세스·메모리 접근은 조사와 제품 어느 쪽에서도 하지 않았다. 게임이 의도적으로 막는 입력을 하드웨어 매크로 등으로 복제하는 방법도 계정 위험 때문에 권하지 않는다.
