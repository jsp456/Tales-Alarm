# Tales Alarm 타이머별 알람 확인 설계

## 목표

알람 음원과 재생시간 설정은 지금처럼 두 타이머가 공유하되, 타이머 완료로 시작된 알람의 소유권은 타이머별로 구분한다. 알람을 발생시킨 타이머를 실제로 조작하면 그 타이머의 알람만 확인 처리하고, 다른 타이머나 미리 듣기가 아직 활성 상태라면 공통 음원 재생을 유지한다.

## 승인된 사용자 동작

- 타이머 1 완료 알람이 울릴 때 타이머 2를 조작해도 알람은 멈추지 않는다.
- 두 타이머의 완료 알람이 모두 활성 상태라면 한 타이머를 조작해도 다른 타이머의 알람 때문에 소리는 계속 난다.
- 마지막으로 남은 완료 알람의 타이머를 조작하면 소리를 즉시 멈춘다.
- 알람을 확인 처리하는 조작은 해당 타이머의 `시작`, `일시정지 / 재개`, `초기화`와 실제로 처리된 전역 단축키 입력이다.
- `입력 무시` 정책으로 동작하지 않은 단축키, 시간·단축키 설정 편집 및 적용, 보기 모드 전환, 다른 타이머 조작은 완료 알람을 확인 처리하지 않는다.
- `미리 듣기`는 타이머 완료 알람과 별도 소유권으로 추적하므로 타이머 조작으로 중단되지 않는다.

## 설정 및 화면 범위

- 현재의 공통 `알람 음원` 화면과 `AlarmSettings`를 그대로 사용한다.
- 타이머별 음원, 타이머별 재생시간, 새 설정 필드나 새 화면은 추가하지 않는다.
- `AppSettings` 스키마 버전과 기존 설정 JSON 형식은 변경하지 않는다.
- 간단 보기와 상세 보기의 레이아웃은 변경하지 않는다.

## 구조

### `TimerAlarmCoordinator`

새 조정기는 저수준 `IAlarmAudioService`를 감싸고 다음 소유권을 관리한다.

- 타이머 번호별 완료 알람
- 미리 듣기

각 활성 항목에는 음원 요청 경로, 기본음 경로, 시작 시각과 만료 시각을 보관한다. 조정기는 주입받은 `TimeProvider`를 사용해 시간을 계산하며 다음 동작을 제공한다.

- `StartTimerAlarm`: 지정한 타이머의 완료 알람을 등록하거나 새 완료 시점 기준으로 갱신한다.
- `StartPreview`: 미리 듣기를 별도 항목으로 등록하거나 갱신한다.
- `AcknowledgeTimer`: 지정한 타이머의 완료 알람만 제거한다.
- `Tick`: 만료된 항목을 제거하고 저수준 오디오 서비스의 반복·종료 처리를 진행한다.

활성 항목이 하나라도 남아 있으면 공통 오디오 재생을 유지한다. 항목이 추가되거나 제거될 때 가장 늦은 만료 시각까지의 남은 시간을 저수준 서비스에 반영한다. 활성 항목이 없으면 `Stop`을 호출한다. 서로 다른 음원을 동시에 겹쳐 재생하는 기능은 추가하지 않으며, 현재 한 개의 공통 오디오 채널을 유지한다. 재생 중 새 항목이 추가되면 현재 재생 중인 음원을 교체하지 않고 소유권과 종료 시각만 갱신한다.

### `TimerViewModel`

`TimerViewModel`은 사용자 조작이 실제로 처리됐을 때 자신의 타이머 번호와 함께 조작 이벤트를 발생시킨다.

- 화면 명령의 시작과 초기화는 처리된 조작이다.
- 실행 중 일시정지와 일시정지 중 재개는 처리된 조작이다.
- 전역 단축키는 `CountdownTimer.HandleActivation`이 시작, 재시작, 일시정지 또는 재개를 수행했을 때만 처리된 조작이다.
- 타이머 완료 이벤트, 주기적 `Tick`, 저장 설정 적용은 사용자 조작 이벤트를 발생시키지 않는다.

`CountdownTimer.HandleActivation`은 입력이 실제로 처리됐는지를 반환해 `ReactivationPolicy.Ignore` 경로를 명확하게 구분한다.

### `MainViewModel`과 미리 듣기

`MainViewModel`은 타이머 완료 이벤트의 발신자에서 타이머 번호를 보존해 조정기에 전달한다. 기존의 출처 없는 `completionPending` 불리언은 `HashSet<int>` 형태의 대기 완료 집합으로 교체하고, 한 번의 화면 갱신 주기에 들어온 모든 타이머 번호를 조정기에 등록한다. 각 `TimerViewModel`의 사용자 조작 이벤트는 같은 번호의 `AcknowledgeTimer`로 연결한다.

사용자 조작 내부에서 완료 이벤트가 먼저 발생한 경우에는 같은 타이머 번호를 대기 완료 집합에서 제거한 뒤 확인 처리해, 다음 화면 갱신에서 알람이 다시 등록되지 않게 한다.

`MainViewModel.Tick`은 성공·실패 여부와 관계없이 조정기의 `Tick`을 호출한다. `AlarmSettingsViewModel`의 미리 듣기는 저수준 오디오 서비스를 직접 호출하지 않고 조정기의 `StartPreview`를 사용한다.

## 시간 및 경계 처리

- 각 완료 알람은 해당 타이머가 완료된 시점부터 현재 공통 설정의 재생시간만큼 유효하다.
- 두 타이머의 완료 시점이 다르면 만료 시점도 독립적이다.
- 같은 타이머가 다시 완료되면 기존 항목을 중복 추가하지 않고 그 타이머의 만료 시점을 갱신한다.
- 재생시간 설정이 활성 알람 사이에 바뀌더라도 각 항목은 자신이 시작될 때 적용된 재생시간을 유지한다.
- 가장 늦은 항목이 먼저 확인 처리되면 남은 항목 중 가장 늦은 만료 시각으로 실제 재생 종료 시점을 앞당긴다.
- 미리 듣기와 완료 알람이 겹치면 한 공통 음원 채널을 공유하지만 소유권과 만료 시각은 각각 유지한다.
- 사용자 음원 열기나 재생 실패 시 기본음으로 대체하는 기존 `AlarmAudioService` 동작을 유지한다.
- 오디오 재생 자체가 실패해 중지됐더라도 소유권 항목은 예정된 만료 또는 사용자 확인까지 안전하게 정리되며, 같은 타이머 조작이 예외를 발생시키지 않는다.
- 앱 종료 시 기존 서비스 폐기 경로가 전체 오디오를 중지한다.

## 검증

### 조정기 단위 테스트

- 타이머 1만 활성일 때 타이머 2 확인은 저수준 `Stop`을 호출하지 않는다.
- 두 타이머가 활성일 때 하나를 확인해도 재생을 유지하고, 마지막 하나를 확인할 때만 중지한다.
- 서로 다른 시점과 재생시간으로 등록된 항목이 각자 만료되며 가장 늦은 만료까지 재생한다.
- 가장 늦은 항목을 먼저 확인하면 남은 만료 시각에 맞춰 종료 시점을 조정한다.
- 같은 타이머의 재완료는 해당 항목의 만료 시각을 갱신한다.
- 미리 듣기만 남은 상태에서는 어떤 타이머 확인도 재생을 중지하지 않는다.

### ViewModel 테스트

- 시작, 일시정지, 재개, 초기화와 처리된 단축키가 올바른 타이머 번호의 조작 이벤트를 발생시킨다.
- `입력 무시`된 단축키, 설정 적용과 `Tick`은 조작 이벤트를 발생시키지 않는다.
- 타이머 1 완료 후 타이머 2 조작으로 알람이 유지되고 타이머 1 조작으로 중지된다.
- 같은 주기에 두 타이머가 완료되어도 두 소유권이 모두 등록된다.
- 미리 듣기가 조정기의 별도 소유권으로 등록된다.

### 회귀 검증

- 전체 Release 테스트를 실행한다.
- 단일 파일 Windows x64 게시와 산출물 실행 검사를 수행한다.
- 기존 음원 반복, 기본음 대체, 설정 저장, 전역 단축키, 간단 보기 동작이 유지되는지 확인한다.

## 제외 범위

타이머별 음원 또는 재생시간 설정, 여러 음원의 동시 재생, 알람 확인 버튼, 알람 상태의 영구 저장, 알람 볼륨 조절은 이번 변경에 포함하지 않는다.
